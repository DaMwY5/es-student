# 3.2. Рекордер звука

Пункты 3.2.1–3.2.7 и 3.2.7д по [методичке курса](https://github.com/ant-lab-ru/es-book/tree/947757f).
Проект основан на `311-adc`; старые проекты и общие библиотеки не изменены.

- В `platform`: таймер индикатора, отсчёты по будильнику, АЦП и DMA, ШИМ GP20,
  сторожевой таймер. Только `platform` управляет этими периферийными блоками.
- `block-task` передаёт готовый блок функции обработки. `stream-task` передаёт
  1030-байтные кадры с синхрословом `a5 5a`, номером и отсчётами.
- При отставании суперцикла считаются переполнения, номера показывают потерю.
  Снимок буфера не даёт USB читать память, которую уже перезаполняет DMA.
  Перед прерыванием каналов цепочка разрывается (RP2040-E13).
- Буферы АЦП и стабильный снимок: 31 456 байт при лимите 32 КиБ.
  Номинальный расчёт с шагом делителя 1/256: около 44 100,07 Гц при такте 48 МГц.
- `rec_audio.py` основан на скрипте курса, но пишет WAV блоками, буферизуя
  только первые 0,1 с для смещения. Обычный WAV ограничен форматом RIFF (около 4 ГиБ).
  При Ctrl+C скрипт отправляет `stream_stop`, дочитывает кадры и закрывает WAV.

## Что проверено без платы

**Все приложенные логи и WAV — результаты программной модели, а не запись с Pico.**
В логах это отмечено в первой строке, в WAV — в метаданных RIFF.
Нулевой серийный номер и USB ID в логах обозначают модель, а не физический прибор.

Модель компилирует настоящие исходники C с подставным SDK. Она вызывает
обработчики таймеров и DMA в виртуальном времени; проверяет переключение режимов АЦП,
двоичные кадры, номера и переполнения, остановку потока и возврат к захвату блока,
сброс сторожевым таймером, а также очистку при прерывании записи.

`melody.wav` получен из модели ШИМ, `recording.wav` и `recording-8bit.wav` —
из одного синтетического тестового сигнала, **не из человеческого голоса**.
Оба файла содержат по 132 096 отсчётов, аудиоданные занимают 264 192 и 132 096 байт.
Модель не подтверждает шум микрофона, фактическую частоту, пропускную способность USB
или время выполнения обработчиков на реальной Pico.

Воспроизведение из корня репозитория (обычный GCC, Python и pyserial):

```text
python tools/test_lesson32.py --generate-model
```

## Сборка и проверка на Pico

Задать `PICO_SDK_PATH` и собрать:

```text
cmake -S 321-audio-recorder -B build/321 -G Ninja
cmake --build build/321
```

С подключённой Pico исходные `check-3-2-*.py` снимают логи. Для мелодии
подключить GP20 к GP26, для записи голоса — заменить перемычку выходом MAX9814
по схеме методички. Из папки проекта:

```text
python rec_audio.py --seconds 5
python rec_audio.py --wav melody.wav --melody
python rec_audio.py --seconds 3 --wav recording.wav
python rec_audio.py --seconds 3 --wav recording-8bit.wav --bits 8
```

Для реальной приёмки нужно заменить модельные артефакты измерениями с платы
и проверить производительность, звук и восстановление после сброса на железе.
